Privacy Policy

Last updated: 15 November 2026

This is the privacy policy for ExplodedStack and its private tool, ExplodedStack Publisher. In short: the tool runs only on the owner's own computer, talks only to the platforms it posts to (YouTube, Facebook and Instagram, and X only if the owner ever turns on the optional X support), and shares nothing with anyone else.

1. Who we are and scope

ExplodedStack is a channel of short explainer videos on YouTube, Instagram, Facebook and X. "ExplodedStack Publisher" (the Publisher) is a private command-line tool written by the channel owner. It uploads the channel's own finished videos to the channel's own YouTube channel, Facebook Page and Instagram professional account through official APIs.

The Publisher is not offered to the public. It has no server, no web app and no other users. The only person who signs in is the channel owner, on the owner's own computer. Because the owner is the only user, this policy is in practice the owner's own statement of what the tool does. Any confirmation or reply described below is given by the owner by hand; no software generates it.

The Publisher does not connect to X by default. X is posted by hand by the owner. The code contains optional, currently unused support for X, which would only run if the owner chose it explicitly.

2. What data the Publisher accesses

Google and YouTube

ExplodedStack Publisher uses YouTube API Services (YouTube Data API v3). It asks for exactly two permissions (OAuth scopes):

  • youtube.upload: permission to upload videos to the owner's YouTube channel.
  • youtube.readonly: permission to read basic channel information. The Publisher uses it only to read the channel title, to confirm that the right channel is signed in. The title is shown in the terminal and is not saved.

When the owner uploads a video, the Publisher sends the video file, title, description, tags, category, privacy and scheduling setting, an AI-content label, a "not made for kids" setting and, optionally, a thumbnail image. YouTube returns the new video's ID and privacy status, which the Publisher saves so it can show the video's link. The Publisher also receives OAuth token responses from Google.

It never lists, edits or deletes existing videos, and never reads comments, analytics or subscribers.

Meta (Facebook and Instagram)

The Publisher uses the Meta Graph API to publish videos to the owner's own Facebook Page and Instagram professional account. To do so it reads the Page and Instagram account identifiers and names, checks the status of uploads in progress and, after an unclear result, reads the IDs and timestamps of the three most recent posts on the owner's own Instagram account to avoid posting twice, and reads the Instagram username and the permalink of a post it has just made. During setup it lists the Pages the signed-in Meta user manages, keeps only the channel's own Page and discards the rest. It then publishes a Reel with a caption, title or description, and an AI-content flag. Which specific Meta permissions the sign-in token carries depends on how the owner's Meta app is configured and is not fixed by this policy.

It does not read or write insights, messages, comments, followers or audience data.

Other people's data

The Publisher does not collect data about other people. It handles only the owner's own accounts and files. It does not read or store any Google, Facebook or X password. Google sign-in happens in the owner's web browser; the Meta access token is pasted by the owner into a hidden prompt.

3. How the data is used

Data is used only to sign in to the owner's own accounts and to upload and publish the owner's own videos, with their titles, descriptions and captions. It is not used for advertising, profiling, analytics, credit or lending, and it is not sold or transferred to anyone. We adhere to this published policy and comply with the privacy laws that apply to us. We only use data in the ways described in this policy, and we will update this page and ask for consent before using data in a new way.

4. Where data is stored and how it is protected

The Publisher stores its files only on the owner's own Windows computer; the only data that leaves it goes to the platforms (section 5). There is no server and nothing is sent to the developer. The Publisher reads the video file, post.json and caption.txt from the owner's disk and writes these files:

FileWhat it holdsProtection
youtube_client.jsonThe Google OAuth client ID and client secretOwner-only file permissions; not encrypted
youtube_token.jsonGoogle access token, refresh token, expiry, scopeOwner-only file permissions; not encrypted
meta.jsonMeta app ID and app secret, Page ID and name, Page access token, Instagram account IDOwner-only file permissions; not encrypted
publish_state.json (one per episode folder)Upload status, resulting video IDs and links, privacy setting, error notes, and the YouTube resumable-upload session addressOrdinary folder permissions; not encrypted
x.jsonX access and refresh tokens, username and user ID. Exists only if the optional X support was set upOwner-only file permissions; not encrypted
x_client.jsonX client ID and secret. Exists only if the owner created it for the optional X support. The owner makes this file by hand, so the Publisher does not restrict its permissionsWhatever the owner set; not encrypted
publish_state.lockA short-lived lock file (process ID and time) in the episode folder while posting; stale ones are removedOrdinary folder permissions
Video copies made for postingRe-encoded or shortened copies of a video (for example x_720x1280.mp4 or facebook_cut90.mp4). They are not deleted automatically and stay in the episode folder until the owner deletes themOrdinary folder permissions

During setup the Publisher reads the Google client file you downloaded from your Downloads folder, copies it to youtube_client.json and deletes the download. The token and secret files written by the Publisher are kept in a private folder and locked to the owner's Windows user account with Windows file permissions (icacls). Files created or copied by hand are not locked by the tool. They are plain files and are not encrypted, and the Publisher does not use an operating-system credential vault. File permissions do not protect against malware running as the same user, against administrators who take ownership of the files, or against someone who has the unencrypted disk. The short-lived and long-lived Meta user tokens used during setup are discarded and not stored.

The Publisher stores sign-in token files on the owner's own computer. It does not set cookies. It has no analytics, telemetry or tracking, and it does not allow third parties to serve content or ads.

5. Sharing

We share nothing with any third party. The only transfers are to the platforms themselves, to do what the owner asked:

  • Google: sign-in credentials and tokens, and the video, title, description, tags, thumbnail and settings being uploaded.
  • Meta: access tokens and the app secret during sign-in, and the video, caption, title, description and AI-content flag being posted.
  • X: only if the owner runs the optional, currently unused X support: tokens, a 720x1280 copy of the video and the post text, sent to X.

Nothing is sent to analytics services, crash-reporting services, GitHub or any developer server. Video processing tools run locally on the owner's computer. The Publisher does not serve content or ads and does not allow third parties to do so.

6. Retention

The Publisher deletes nothing automatically. Everything it stores is kept until the owner deletes the files by hand. The only built-in removal is the --forget option, which removes one platform's record from publish_state.json on request and adds a "forgotten" entry.

  • Sign-in tokens and client files stay on the computer until the owner deletes them. The Google token file is overwritten in place whenever the token is refreshed.
  • Upload records (publish_state.json, video IDs and links) stay in the episode folder until the owner deletes them.
  • Video copies made for posting (such as x_720x1280.mp4, x_720x1280.tmp.mp4 left by a failed run, and facebook_cut90.mp4) are not deleted automatically and stay until the owner deletes them.
  • Owner's practice (a manual commitment, not a software feature): the owner deletes stored YouTube API data, and Facebook and Instagram data, when it is no longer needed, when the owner stops using the Publisher, or on request, and within the time stated in section 8.
  • Already published videos and posts remain on the platforms until they are deleted there.

7. Revoking access

Deleting a token file on the computer removes the local copy but does not revoke access at the platform. To revoke:

  • Google and YouTube: you can revoke ExplodedStack Publisher's access to your Google account at any time at Google account permissions page. You can also delete the local token file.
  • Facebook and Instagram: remove the app in your Facebook or Instagram account settings, in the section for business integrations or apps and websites. Menu names may change over time.
  • X (only if the optional support was ever used): remove the app in X's connected-apps settings.

After revocation or deletion the Publisher simply cannot post until the owner signs in again. The Publisher has no revoke or logout command and does not detect revocation. After revoking at Google's permissions page, the owner deletes youtube_token.json and youtube_client.json by hand. This is a manual commitment by the owner: the owner does so within 7 days of learning of the revocation.

8. Data deletion instructions

This section is the data deletion instructions page for Meta, and applies equally to Google data. The Publisher has no server and no accounts, so the only data held is on the owner's own computer. To have data deleted:

  1. Remove the app from your platform account: on Facebook or Instagram, remove it in your account settings under business integrations or apps and websites. For Google, use the link in section 7.
  2. Delete the stored data on the computer: the files listed in section 4 (youtube_client.json, youtube_token.json, meta.json, x.json and x_client.json if they exist, and the publish_state.json, publish_state.lock and video-copy files in the episode folders).
  3. If you cannot do this yourself or want a written confirmation, contact us using the link in section 13 with the subject "Data deletion". The owner replies by hand, within 7 days, with a reference code and a plain-language status of your request, including the reason if it cannot be completed. Nothing is generated automatically.

The owner deletes stored Google, Facebook and Instagram data by hand within 7 calendar days of a request. This is a manual commitment, not an automated process. Deleting data here does not delete content on YouTube, Facebook or Instagram, or your account; that is governed by each platform's own policies and tools.

9. Google API Services and YouTube

  • ExplodedStack Publisher uses YouTube API Services (YouTube Data API v3) to upload videos to the owner's own YouTube channel, and is subject to the YouTube API Services Terms of Service.
  • By using the Publisher with YouTube you are bound by the YouTube Terms of Service.
  • Google's handling of data is described in the Google Privacy Policy (https://policies.google.com/privacy).
  • ExplodedStack Publisher's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. Data is used only to upload the owner's own videos, is not transferred to anyone other than Google and the other platforms the owner posts to, is not used for advertising, and is not used for credit or lending.
  • You can revoke access at any time (see section 7).

10. This website

This website is static. It sets no cookies of its own, uses no analytics, loads no scripts, fonts or other resources from other sites, and uses no advertising. It is hosted on GitHub Pages, which may record standard server logs such as visitors' IP addresses under its own policy: see the GitHub Privacy Statement. We do not receive or use those logs.

11. Children

The Publisher and this website are not directed at children and do not knowingly collect data from them. The Publisher collects no data about viewers at all.

12. Changes

If we change this policy we will update this page and the date at the top. We will not use data in a new way without updating this policy first and asking for consent where required.
